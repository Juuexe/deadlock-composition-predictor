# Release status

The manual composition app is implemented with supported-hero selection, search, portraits, composition prediction, validation evidence, lineup links and experimental partial-draft recommendations. The release candidate is 5c094e85ad12, supporting all 42 active heroes including Deadman Danny; it passed the frozen roster-expansion holdout. Deployment verification is pending. The old model 3debc4970fe5 and its historical reliability snapshot are retained separately. The predictor and draft feature accept composition only.

The October 13 roster announcement closed the old frozen reliability period. Research for the newest October 15 03:11:58 UTC gameplay period produced a separate candidate, without reusing reliability labels for development. The prior calibration candidate remains preserved and blocked, with its test unopened. See roster-update-assessment.md for new data, counts, results and limitations.

The experimental public beta is live at https://deadlock-composition-predictor.vercel.app in julius-projects6. Vercel CLI authentication resolved the earlier connector permission failure. Server-only MODEL_JSON/HEROES_JSON are encrypted secrets; datasets and model files were excluded from the upload. Production health, hero catalog, matching aggregate evidence, prediction, draft suggestions, share restoration and rejection of invalid/player inputs were verified. Private data/model/environment URLs returned 404. All 32 tests and the repository type check passed in the hosted build. The platform's separate TypeScript transpilation emitted a node type-definition warning, although deployment and runtime checks succeeded; inspect this on the next platform/compiler upgrade.

The roster candidate passed all explicit coverage-expansion gates on 6,720 single-use held-out matches, including 5,677 Danny matches and 1,043 shared-hero matches. The app labels this evidence as a chronological holdout; it never attributes the old model's prospective reliability results to the new model. New prospective multi-day monitoring remains outstanding.

Automatic detection is a feasibility limitation: the community active-match API only covers the top 200 watch-tab matches. Universal match discovery and five-second startup latency have not been established. A verified match source or supported local integration is required before implementing that later feature.

No full-draft strategy, causal recommendation quality, exact 58% calibration or future-patch accuracy is claimed. Production load testing and automatic detection remain unverified. The new model has short-period holdout evidence, not established multi-day or future-patch reliability.
